# SAT-only satellite recovery — observed 7–8 November 2026

**Device:** GTMedia GTX Combo; **build:** CoreELEC 22 Piers RC1; **kernel:** 5.15.196. These findings are derived from the receiver operator's supplied console outputs and confirmations. Full original logs, proprietary firmware and the captured transport stream have not been uploaded here.

## Before the intervention

- The kernel attached `Montage m88rs6060` at `/dev/dvb/adapter0/frontend0`; FE lock was reported on a test transponder.
- DVB demux/direct transport capture produced **0 bytes** even with lock.
- The experimental device tree exposed a **single SAT frontend**, TS1 parallel, `ts1_control=0x800`.

## Historical diagnosis and intervention (not general instructions)

1. The operator checked controller identities: `ffe07000.emmc` was the eMMC controller; `ffe05000.sd` corresponded to unused SD host `mmc1`. Pin `GPIOC_5` (gpiochip1 offset 47) was claimed by the SD host.
2. After confirming `mmc1` had no card, that SD host was unbound on this device and the GPIO pin was observed unclaimed.
3. The operator's pre-existing CIMaX GPIO helper toggled that pin, after which USB VID:PID `1b0d:2f00` enumerated in boot mode (`bcdDevice=0001`).
4. Operator-held CIMaX firmware and a configuration utility were applied; runtime `bcdDevice=0000` was observed. **Some configuration register readbacks did not match**, so full register-level correctness is not established.
5. The active SAT-only routing was `source=dmx0`, `demux0_source=ts1`, `demux1_source=ts0`.
6. Transport-stream capture then returned **83,361,792 bytes**, with MPEG-TS synchronization at 188-byte packet intervals. TVHeadend channel reception was operator-confirmed.

## Reboot-readiness fix

On the initial reboot, a startup systemd service failed before the DVB frontend node appeared; the kernel later attached the M88RS6060 (approximately 14.1 seconds into the boot). Manually rerunning the existing setup after frontend readiness succeeded.

The operator added a systemd drop-in **only for the SAT-only frontend0 arrangement**:

```ini
[Service]
ExecStartPre=/bin/sh -c "until [ -c /dev/dvb/adapter0/frontend0 ]; do sleep 1; done"
TimeoutStartSec=150
```

After **one** further reboot, the operator confirmed satellite reception without manually restarting the service. A full post-reboot service log was not captured; automatic success of the unit is a *reasonable inference*, not a separately logged observation.

## What remains unverified

- A cold power-off/power-on and repeated restart reliability.
- A dual-frontend SAT + Sony DVB-T/T2 configuration.
- An exact register-level root cause and device-tree ownership fix.
- Reproducibility on another GTX board revision or any GT Combo.
- Safety of the GPIO, MMC unbinding or routing on other boards.

The reference script can change device state. This note is **not** a universal setup guide or redistribution of proprietary firmware.
